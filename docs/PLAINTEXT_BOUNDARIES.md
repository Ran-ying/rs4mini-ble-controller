# 明文业务解析边界（0.7.29 / 原生0.3.29 build32）

DUML CRC 正确只证明帧完整，不证明业务体可按明文解析。SDK 不实现厂商加密或自动协商；加密报文继续作为原始消息提供，但不得用于以下业务解码。

- App 关联响应要求 flags 为整数 uint8、ACK 位为1、低三位加密标志为0，并且业务体非空。加密或无效标志返回 RS4MINI_PROTOCOL_ERROR，而不是读取首字节判定成功/设备错误。请求关联仍由既有会话、序号、端点与命令检查负责。
- 04:05 反馈与04:6E自动调参通知要求明文请求型帧；加密帧不更新姿态、关节或状态缓存，不给 moveTo 提供反馈。
- 旧 rs3/rs3mini 研究状态解析要求明确有效且未加密的 flags；其原有 ACK/请求型差异保持。
- 纯 Node/Python 整帧解码函数现在要求显式 flags；缺失、布尔、非整数及超出0..255均拒绝。原生 RSDecodeTelemetry 是 payload-only 帮助函数，调用方仍负责报文头；RSBleDevice 在调用前验证请求位与加密位。
- 原始 CRC 合法帧仍到达原始消息观察者；拒绝结构解码不删除原始证据，不新增 ACK、订阅、写入或解密。

回归覆盖全部非零加密模式、合法成功/失败响应、坏标志、加密读取不推进参数读改写、状态缓存不被污染，以及定位等待期间假关节反馈不生效。Web 使用共享 JS 核心，原生使用假设备，不连接硬件。

这次修复不开放04:08校准触发，不改变48项命令清单及两个false完成门槛。[角度包层审计](../tools/research/ANGLE_CONTEXT.md)说明 App 业务 doPack 的 Encrypt.NO 不能单独证明最终线上层没有条件加密；本机模式与协商尚未验收。其余缺口见[命令审计](SDK_COMMANDS.md)。
