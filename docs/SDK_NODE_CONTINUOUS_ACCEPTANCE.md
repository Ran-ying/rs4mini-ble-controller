## 覆盖边界与剩余项

- 回中已补齐：用户先授权完整回中，后说明原先已在中间并明确要求大范围移动。第一轮工具误把关节Yaw0当回中参照，触发无依据的断言，原始失败记录保留并分类为测试判据错误。修正后以实测起点作参照，按授权执行15.77°偏离后回中，差0.01°且反馈稳定；用户确认清楚看到回中、无异常。这不证明任意安装状态、所有轴偏离或所有负载都有同样精度，也不建立机械Yaw零点与物理回中的关系。
- 两个校准入口本轮按用户要求排除，保留之前三端完成及用户确认的证据。微调同样沿用之前的受控反馈与用户可见效果证据。
- 正常`getAttitude()`、`getJointAngles()`的新帧读取通过；实验区`query({kind:'position'})`超时是另一个其他型号来源的原始命令，不能与正常反馈读取混为一谈。其他型号休眠/绝对角/原生速率不试发，不推断本机兼容。
- 单次程序状态请求三个program均ACK0，但不承诺收到与请求相关的新状态、启动任何程序或物理完成。被动推送这轮只观察到abnormal/program；其余8个缓存没有新流量，不把空缓存当解码实测通过。历史校准进度另有实测。
- CENTER只测既有Ver1_1来源布局；其他版本的解析和发送向量通过离线检查，不代表已识别当前固件会话格式。身份和完整原始帧只保存在忽略目录，未提交。
- 所有普通写入先备份、同值写回、ACK0后回读比较；只有灵敏度0↔1后恢复。独立参数要求输入源本来已为2才写同值，未切换输入源；跟随加速度仍三轴1，Low档位保持。没有验证每个数值、模式切换后的效果或重启持久化。

因此，本轮普通SDK批次通过，实验区位置候选仍失败；不宣称全部公开研究接口已获本机支持，也不宣称全部BLE命令已实现。全协议和高级开发门槛仍false。

## 连续复现

需要用户在场且满足各工具对应的授权。一次一个控制端；这些工具不进入默认测试/CI，默认缺少显式开关时在创建蓝牙实例前退出。

```sh
RS4MINI_SDK_TEST=yes RS4MINI_ALLOW_SETTINGS=yes RS4MINI_DEVICE_ID='<本机设备标识>' node tools/hardware/sdk-node-continuous.mjs
RS4MINI_SDK_TEST=yes RS4MINI_ALLOW_SMALL_MOTION=yes RS4MINI_DEVICE_ID='<本机设备标识>' node tools/hardware/sdk-node-small-motion.mjs
RS4MINI_SDK_TEST=yes RS4MINI_DEVICE_ID='<本机设备标识>' node tools/hardware/sdk-node-research-queries.mjs
```

第三条预期会记录当前position超时并返回退出码1，不用过滤失败来得到全绿。原始报文和写入前备份在`node/captures`，不提交Git。stdout摘要可归档。

三轴回中另用`tools/hardware/sdk-node-recenter.mjs`，必须显式设置`RS4MINI_ALLOW_FULL_RECENTER=yes`。复现本次15°偏离需再设置`RS4MINI_ALLOW_LARGE_MOTION=yes RS4MINI_RECENTER_YAW_OFFSET_DEG=15`，仅接受固定15；25°护栏、20秒偏离截止时间、反馈丢失停止。初始参考必须是已确认的设备正常中位。默认不加偏离开关只记录回中和稳定反馈，不能在原本已居中时证明离中返回效果。

## 其他端与Node的一致性

Node为收发基准。Python/macOS需要对同一请求和响应向量核对字节、端点、ACK关联、符号/宽度、枚举及短包行为；还需测试各自的连接、通知重组、超时、取消和关闭。只有收发字节一致，不能推导所有平台生命周期均正确。

本轮其他端只做离线回归：Node243、Python3.8 SDK223、研究558、原生1562核心+256生命周期+3独立SDK+210GUI适配检查，严格TypeScript、分层检查和签名构建均通过。没有启动其他端蓝牙或GUI。之前三端基础与维护实测记录继续有效，见[逐项队列](SDK_ACCEPTANCE_QUEUE.md)。
